Core Cloud Services Explained

Services are organized from basic to advanced

COMPUTE

Virtual Machines (VMs)

Origin: From traditional data centers; virtualization technology popularized by VMware in the 1990s

What it is: On-demand computing resources where you rent entire virtual computer instances with configurable CPU, RAM, and storage

When to use: Legacy application migration, full control over OS, complex multi-tier applications, high computational needs

Pros: Full control, mature technology, wide OS support, scalable, cost-effective for sustained workloads

Cons: Requires OS maintenance, slower startup, less automatic scaling, higher baseline cost

Cost: $0.01-$5/hour depending on instance size; monthly bills typically $10-$500+

Building-Block Concepts & Tools
Hypervisor (KVM/Xen) vCPU / CPU Pinning Virtual Disk (EBS/vHD) Virtual NIC AMI / VM Image Auto Scaling Group SSH Key Pair Security Group / Firewall Rules Spot / Preemptible Instance Placement Group
COMPUTE

Container Services (Docker, Kubernetes)

Origin: Docker (2013); Kubernetes evolved from Google's internal Borg system, open-sourced in 2014

What it is: Lightweight, portable application packaging with automatic orchestration and scaling

When to use: Microservices architecture, rapid deployment, DevOps workflows, consistent dev/prod environments

Pros: Lightweight, fast startup, excellent scalability, easier DevOps, cost-efficient, multi-cloud friendly

Cons: Steep learning curve, complex orchestration, security considerations, requires container registry management

Cost: $0.004-$0.25/hour for container instances; managed services $30-$200+/month

Building-Block Concepts & Tools
Dockerfile Container Image / Registry Pod (Kubernetes) ReplicaSet / Deployment Service & Ingress Namespace Helm Chart kubectl / CLI ConfigMap & Secret Persistent Volume (PV/PVC)
COMPUTE

Serverless/Functions (Lambda, Functions)

Origin: AWS Lambda (2014); abstraction layer over containerization, inspired by functional programming

What it is: Write code without provisioning servers; automatically scales and charges only for execution time

When to use: Event-driven tasks, APIs, data processing, scheduled jobs, microservices, prototyping

Pros: Zero management, extreme scalability, pay-per-use pricing, fast deployment, ideal for spiky traffic

Cons: Cold start latency, execution time limits, vendor lock-in, complex debugging, cost unpredictable

Cost: $0.0000002/GB-second; typically $0-$100/month for most applications

Building-Block Concepts & Tools
Event Source / Trigger Execution Context Cold Start Concurrency Limit Timeout Environment Variables Layers / Extensions API Gateway Dead Letter Queue (DLQ) IAM Role / Permission
STORAGE

Object Storage (S3, Blob Storage)

Origin: AWS S3 (2006); revolutionized data storage with REST API and unlimited scalability

What it is: Unlimited, scalable storage accessed via API/URLs; ideal for unstructured data like files, images, backups

When to use: Media storage, backups, log files, static website hosting, data lakes, archive

Pros: Unlimited scale, very cheap, 99.9%+ availability, built-in replication, easy to use

Cons: Not for frequently changing files, not ideal for databases, latency for small files, egress charges

Cost: $0.023/GB/month storage; data transfer charges apply

Building-Block Concepts & Tools
Bucket / Container Object Key / Path Storage Class (Standard/IA/Glacier) Lifecycle Policy Versioning Presigned URL Bucket Policy / ACL Replication (CRR/SRR) Multipart Upload Event Notification
STORAGE

Managed Databases (RDS, Cloud SQL)

Origin: Traditional SQL databases (1970s); cloud versions started with Amazon RDS (2009)

What it is: Pre-configured database engines (MySQL, PostgreSQL, Oracle) with automatic backups and scaling

When to use: Structured data, relational requirements, ACID compliance, complex queries, traditional apps

Pros: Managed backups, automatic scaling, high availability, minimal admin work

Cons: Less flexible than self-managed, potential vendor lock-in, can be expensive at scale

Cost: $0.04-$0.50/hour for instances; ~$30-$1000+/month depending on size

Building-Block Concepts & Tools
DB Instance / Cluster Read Replica Multi-AZ / HA Automated Backup & PITR Parameter Group Connection Pooling (PgBouncer/RDS Proxy) Subnet Group / VPC Storage Engine (InnoDB/MyRocks) Slow Query Log Snapshot & Restore
STORAGE

NoSQL Databases (DynamoDB, Firestore)

Origin: MongoDB (2009), Cassandra (Facebook, 2008); designed for modern, flexible data models

What it is: Non-relational databases with flexible schemas; optimized for scale and high-speed reads/writes

When to use: Real-time apps, IoT data, user profiles, flexible schemas, massive scale, rapid prototyping

Pros: Massive scalability, flexible schemas, very fast, great for real-time applications

Cons: Complex queries harder, no ACID guarantee, consistency trade-offs, learning curve

Cost: Pay-per-request: $1.25 per million requests; provisioned: ~$1/hour base

Building-Block Concepts & Tools
Partition Key / Sort Key Document / Collection Global Secondary Index (GSI) Sharding Eventual vs Strong Consistency Time-to-Live (TTL) Streams / Change Feed Transactions (multi-item) DAX / In-Memory Cache Schema-on-read
NETWORKING

Content Delivery Network (CDN)

Origin: Akamai (1998); evolved to become standard infrastructure for fast content delivery

What it is: Global network of servers caching and serving your content from locations closest to users

When to use: Website acceleration, video streaming, global audience, static asset distribution

Pros: Dramatically faster for end-users, reduces origin server load, DDoS protection

Cons: Additional cost, cache invalidation complexity, not ideal for dynamic content

Cost: $0.085/GB for outbound data in US; $0.085-$0.50/GB globally

Building-Block Concepts & Tools
Edge / PoP Location Origin Server Cache-Control / TTL Headers Cache Invalidation Geo-Restriction HTTPS / TLS Termination WAF Integration Signed URL / Signed Cookie Anycast Routing HTTP/2 & HTTP/3
NETWORKING

Load Balancing

Origin: Layer 4 load balancers (1990s); evolved to intelligent Layer 7 routing

What it is: Automatically distributes incoming traffic across multiple backend servers for high availability

When to use: Multi-region deployment, rolling updates, fault tolerance, scaling applications

Pros: High availability, automatic failover, health checking, simple traffic distribution

Cons: Additional latency, potential single point of failure if not configured properly

Cost: $0.006/hour; ~$5-$20/month base; charges per LB rule

Building-Block Concepts & Tools
Target Group / Backend Pool Health Check Listener Rule Round-Robin / Least-Connections Sticky Sessions SSL/TLS Offloading Cross-Zone Load Balancing Layer 4 (TCP/UDP) vs Layer 7 (HTTP) Connection Draining Path-Based Routing
AI/ML

Machine Learning Platforms

Origin: TensorFlow (Google, 2015); cloud ML offerings started with AWS SageMaker (2017)

What it is: Managed services for training, deploying, and managing ML models with pre-built algorithms

When to use: Predictive analytics, computer vision, NLP, recommendation systems, classification tasks

Pros: Pre-built models, automatic scaling, integrated with other services, reduced time to model

Cons: Expensive at scale, vendor-specific models, learning curve steep, not always best custom models

Cost: $0.30-$2.00 per GB for training; inference $0.0001-$0.001 per prediction

Building-Block Concepts & Tools
Training Job / GPU Instance Model Artifact / Registry Feature Store Data Labeling Hyperparameter Tuning Inference Endpoint Notebook (Jupyter) Pipeline / Workflow AutoML Model Monitoring & Drift Detection
ANALYTICS

Data Warehouse (BigQuery, Redshift)

Origin: Teradata (1979); cloud data warehouses emerged with Google BigQuery (2010)

What it is: Massive-scale SQL database optimized for analytical queries and data aggregation

When to use: Business intelligence, data analysis, report generation, petabyte-scale analytics

Pros: Extreme scalability, SQL familiar to many, serverless, extremely fast queries

Cons: Can be very expensive with large data scans, learning curve, not ideal for transactions

Cost: $5-$40 per TB scanned; on-demand pricing preferred over reserved

IoT

IoT Hub & Messaging

Origin: MQTT protocol (1999); cloud IoT services launched with AWS IoT (2015)

What it is: Platform for connecting, managing, and processing data from billions of IoT devices

When to use: Smart devices, sensor networks, real-time monitoring, device management at scale

Pros: Massive device support, built-in security, real-time processing, device management

Cons: Complex setup, steep learning curve, can be expensive with many device connections

Cost: $5-$10/month per 1M device connections; data transfer charges apply

Building-Block Concepts & Tools

Foundational concepts and tools that underpin every cloud service, ordered from basic to advanced

COMPUTE

Hypervisor (KVM / Xen / Hyper-V)

Origin: IBM CP-40 (1967); open-source KVM merged into Linux kernel (2007)

What it is: Low-level firmware/software that abstracts physical hardware, enabling multiple VMs to share one physical host with isolated CPU, memory, and I/O

When to use: Underlies every VM-based cloud service; direct interaction rarely needed by end users unless running bare-metal or nested virtualisation

Pros: Strong isolation, mature, hardware-level performance; supports live migration

Cons: Overhead vs containers, requires hardware support (VT-x/AMD-V)

Cost: Included in VM pricing; no separate charge

COMPUTE

VM Image / AMI / Snapshot Template

Origin: Disk imaging tools (Ghost, 1995); cloud AMI concept introduced by AWS (2006)

What it is: A pre-configured OS + software blueprint used to stamp out identical VM instances instantly

When to use: Golden-image pipelines, auto-scaling groups, reproducible environments

Pros: Fast provisioning, immutable infrastructure, easy rollback

Cons: Image drift if not rebuilt regularly; large storage size

Cost: Snapshot storage ~$0.05/GB/month

COMPUTE

Dockerfile & Container Image

Origin: Docker Inc. (2013); based on Linux namespaces & cgroups available since 2007

What it is: A text recipe (Dockerfile) that builds a layered, portable container image — the unit of deployment for containerised workloads

When to use: Any containerised application; CI/CD image build pipelines

Pros: Reproducible, small layers cached for speed, multi-arch support

Cons: Large images if not optimised; layers can expose secrets if not careful

Cost: Build compute cost only; registry storage ~$0.10/GB/month

COMPUTE

Kubernetes Pod, Deployment & Service

Origin: Google Borg (2003); open-sourced as Kubernetes (2014)

What it is: A Pod is the smallest deployable unit (one or more containers sharing network/storage). A Deployment manages replicas; a Service exposes them via stable DNS

When to use: Any containerised workload requiring self-healing, rolling updates, or horizontal scaling

Pros: Declarative, self-healing, huge ecosystem

Cons: YAML complexity, steep learning curve, cluster management overhead

Cost: Control plane $0.10/hour on EKS/GKE/AKS; worker nodes separate

COMPUTE

Helm Chart

Origin: Deis (2016); graduated CNCF project

What it is: A package manager for Kubernetes; bundles all K8s manifests into a versioned, parameterisable chart for easy install/upgrade/rollback

When to use: Packaging and distributing Kubernetes applications; environment-specific overrides via values.yaml

Pros: Versioned releases, templating, large public chart repository

Cons: Template complexity; Helm 2 Tiller security issues (resolved in Helm 3)

Cost: Free (open-source); no cloud-provider charge

COMPUTE / NETWORKING

API Gateway

Origin: AWS API Gateway (2015); concept from SOA ESBs (2000s)

What it is: A managed front-door for HTTP/WebSocket APIs: routing, auth, throttling, request transformation, caching, and metering in one service

When to use: Exposing Lambda functions, microservices, or REST/GraphQL APIs publicly or to internal consumers

Pros: Zero server management, built-in auth (JWT/OAuth), automatic throttling and docs

Cons: 29-second timeout on AWS; latency overhead; complex pricing

Cost: ~$3.50 per million REST API calls; WebSocket $1.00 per million messages

STORAGE

Storage Classes & Lifecycle Policies

Origin: AWS S3 Glacier (2012); extended with Intelligent-Tiering (2018)

What it is: Rules that automatically transition objects to cheaper tiers (e.g., Standard → Infrequent Access → Glacier) based on age or access patterns

When to use: Any data with decreasing access frequency; archive after 90/180 days

Pros: Automatic cost reduction, no code changes needed

Cons: Retrieval fees and delays for cold tiers; minimum storage durations apply

Cost: S3 Standard $0.023 → IA $0.0125 → Glacier $0.004/GB/month

STORAGE

Connection Pooling (PgBouncer / RDS Proxy)

Origin: PgBouncer (2007); RDS Proxy (AWS, 2020)

What it is: A proxy that sits between application and database, multiplexing many app connections into a small pool of real DB connections — critical for serverless/Lambda environments

When to use: Serverless functions hitting a relational DB; apps with many short-lived connections

Pros: Prevents DB connection exhaustion; faster connection acquisition

Cons: Adds latency hop; does not support all SQL features in transaction mode

Cost: RDS Proxy $0.015/vCPU-hour of the underlying DB

STORAGE

Read Replica & Multi-AZ

Origin: MySQL replication (2001); cloud Multi-AZ by Amazon RDS (2010)

What it is: Read Replicas are async copies of a primary DB for read-scale. Multi-AZ is a synchronous standby for automatic failover with no data loss

When to use: Read Replica: read-heavy apps, reporting. Multi-AZ: any production database requiring HA

Pros: Read scale-out; zero-downtime failover with Multi-AZ

Cons: Replication lag on replicas; Multi-AZ doubles cost

Cost: Each replica ~same as primary instance cost

STORAGE

Global Secondary Index (GSI) & Sharding

Origin: DynamoDB GSI (2013); consistent hashing sharding from Dynamo paper (Amazon, 2007)

What it is: GSI: an alternate index on different attributes enabling flexible query patterns. Sharding: distributing data across partitions by a hash key for horizontal scale

When to use: GSI: multiple access patterns on same table. Sharding: when a single partition cannot handle throughput

Pros: GSI adds query flexibility; sharding removes hotspots

Cons: GSIs add storage and write cost; poor shard-key choice causes hot partitions

Cost: DynamoDB GSI: same RCU/WCU cost as base table

NETWORKING

Cache-Control Headers & TTL

Origin: HTTP/1.1 spec RFC 2616 (1999)

What it is: HTTP response headers (Cache-Control, ETag, Last-Modified) that instruct CDN edge nodes and browsers how long to cache a resource before re-validating

When to use: Tuning CDN cache hit rate; differentiating static (long TTL) from dynamic (short/no-cache)

Pros: Zero infrastructure cost optimisation; dramatic reduction in origin load

Cons: Stale content risk; invalidation required after deploy

Cost: No direct cost; reduces egress charges by improving cache-hit ratio

NETWORKING

Health Check & Circuit Breaker

Origin: Load-balancer health probes (1990s); Circuit Breaker pattern by Michael Nygard (2007)

What it is: Health checks probe backend instances (HTTP/TCP/gRPC) at intervals; circuit breakers in service mesh stop routing to a failing service temporarily to prevent cascade failures

When to use: All production load-balanced services; microservices with external dependencies

Pros: Automatic removal of unhealthy nodes; prevents cascade failures

Cons: False positives can remove healthy nodes; requires tuning thresholds

Cost: Included in load-balancer pricing

SECURITY

IAM Role & Policy (Least Privilege)

Origin: AWS IAM (2011); Zero Trust principles formalised by Google BeyondCorp (2014)

What it is: Identity & Access Management defines WHO (identity) can do WHAT (action) on WHICH resource via JSON policy documents; roles are assumable without long-lived credentials

When to use: Always — every cloud resource should have the minimum required permissions; machine-to-machine auth

Pros: No static passwords; auditable; fine-grained control

Cons: Policy complexity; misconfiguration risk (over-permissive wildcard)

Cost: Free in all major providers

NETWORKING

VPC, Subnet & Security Group

Origin: AWS VPC (2009); inspired by traditional VLAN/firewall concepts

What it is: Virtual Private Cloud: a logically isolated network within a cloud region. Subnets split it into public/private zones. Security Groups act as stateful per-instance firewalls

When to use: All production workloads; needed to isolate databases from the internet

Pros: Network-level isolation, free, flexible CIDR ranges, peering between VPCs

Cons: Complex multi-VPC routing; NAT Gateway is expensive for high-egress workloads

Cost: VPC free; NAT Gateway ~$0.045/hour + $0.045/GB data

AI/ML

Feature Store

Origin: Uber Michelangelo (2017); AWS SageMaker Feature Store (2020)

What it is: A centralised repository for ML features — computed once, shared across multiple models. Provides offline (training) and online (low-latency inference) stores

When to use: Teams building multiple ML models that share common feature computations; preventing training-serving skew

Pros: Reduces redundant computation; consistency between training and inference

Cons: Added infra complexity; latency for online retrieval

Cost: SageMaker Feature Store ~$0.00027/write unit + $0.00018/read unit

ANALYTICS

Columnar Storage & MPP

Origin: MonetDB (1993); commercialised by Vertica, Redshift (2012)

What it is: Storing data column-by-column rather than row-by-row allows compression and skipping irrelevant columns. MPP distributes query execution across many nodes in parallel

When to use: Aggregation-heavy analytics, BI dashboards, large-scale data scans

Pros: 10-100× faster aggregations than row-store; high compression

Cons: Slow for single-row lookups; insert/update overhead

Cost: Included in data-warehouse pricing; affects query cost in BigQuery per TB scanned

ANALYTICS

ETL / ELT Pipeline

Origin: ETL coined in the context of data warehousing (1970s); ELT shift enabled by cloud DW power (2010s)

What it is: ETL: Extract → Transform → Load. ELT: load raw data first, transform inside the warehouse. Tools: Apache Spark, dbt, AWS Glue, Fivetran

When to use: Moving data from operational systems into analytics stores; data normalisation and enrichment

Pros: ELT leverages DW compute power; decouples ingestion from transformation

Cons: Transformation complexity; data quality issues propagate downstream

Cost: AWS Glue $0.44/DPU-hour; self-managed Spark on EMR $0.015-$0.20/hour per node

IoT

MQTT Protocol & Device Shadow / Twin

Origin: MQTT invented by IBM (1999) for satellite pipelines; Device Shadow concept by AWS IoT (2015)

What it is: MQTT: lightweight publish-subscribe messaging over TCP, ideal for constrained devices. Device Shadow: a JSON document in the cloud mirroring the last-known and desired state of a physical device

When to use: IoT telemetry ingestion; offline device state synchronisation

Pros: Very low bandwidth; offline-resilient with Shadow; QoS levels

Cons: No built-in security (must layer TLS + auth); broker becomes SPOF without HA setup

Cost: AWS IoT: $0.30 per million messages (≤512 bytes)

IoT / ANALYTICS

Time-Series Database

Origin: RRDtool (1999); InfluxDB (2013); AWS Timestream (2020)

What it is: A database optimised for sequential, timestamped data (sensor readings, metrics, events) with automatic downsampling, retention, and fast range queries

When to use: IoT sensor ingestion, application performance monitoring, financial tick data

Pros: Extreme write throughput; built-in aggregation functions; automatic data expiry

Cons: Not general-purpose; poor for complex relational queries; vendor lock-in

Cost: AWS Timestream $0.036/million writes; $0.01/GB/month storage
