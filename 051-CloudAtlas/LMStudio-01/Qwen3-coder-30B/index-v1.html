Detailed Cloud Service Descriptions

Virtual Machines
Origin: Introduced by Amazon in 2006 as part of AWS
What it is: Elastic Compute Cloud (EC2) provides scalable compute capacity in the cloud.
How it works: Users can launch virtual machines with various configurations and operating systems.
When to use: For running applications that require dedicated computing resources or need full control over the operating system.
Pros: Scalability, flexibility, pay-as-you-go pricing, various instance types.
Cons: Requires more management overhead compared to managed services, potential for cost overruns.
Cost: $0.01 - $4.50/hour depending on instance type and region.
Storage (S3)
Origin: Amazon Simple Storage Service (S3) launched in 2006 as part of AWS
What it is: Object storage service for storing and retrieving any amount of data.
How it works: Data is stored in buckets with key-value pairs, providing RESTful API access.
When to use: For storing large amounts of unstructured data, backup and archive, content delivery.
Pros: Highly durable, scalable, multiple storage classes, global accessibility.
Cons: Not suitable for low-latency applications, potential cost for frequent access.
Cost: $0.023/GB/month for standard storage, $0.0125/GB/month for reduced redundancy.
Database (RDS)
Origin: Relational Database Service launched in 2009 by AWS
What it is: Managed database service supporting multiple engines (MySQL, PostgreSQL, Oracle).
How it works: Provides automated backups, patching, and scaling with minimal administration.
When to use: For applications requiring relational database capabilities with managed infrastructure.
Pros: High availability, automated backups, easy scaling, integrated with other AWS services.
Cons: Limited customization, potential for vendor lock-in, higher cost than self-managed.
Cost: $0.12 - $1.50/hour depending on instance type and database engine.
Serverless (Lambda)
Origin: AWS Lambda launched in 2014 as part of AWS Serverless Computing
What it is: Event-driven compute service that runs code in response to triggers.
How it works: Code is executed in response to events like HTTP requests, database changes, or scheduled tasks.
When to use: For event-driven applications, microservices, or any code that should run only when needed.
Pros: No server management, automatic scaling, pay-per-execution pricing.
Cons: Cold start delays, limited execution time (15 minutes max), debugging challenges.
Cost: $0.20 per million requests, $0.00001667 per GB-second for compute time.
Machine Learning (SageMaker)
Origin: Amazon SageMaker launched in 2017 as part of AWS AI/ML services
What it is: Fully managed service for building, training, and deploying machine learning models.
How it works: Provides built-in algorithms, Jupyter notebooks, and automated ML capabilities.
When to use: For developers and data scientists who want to build ML models without infrastructure management.
Pros: No infrastructure management, pre-built algorithms, easy deployment.
Cons: Can be expensive for small projects, limited customization options.
Cost: $0.10 - $2.00 per hour for training instances, $0.05 per hour for hosting.
Big Data Processing (EMR)
Origin: Amazon EMR launched in 2009 based on Apache Hadoop ecosystem
What it is: Managed Hadoop service for processing large data sets.
How it works: Runs Hadoop, Spark, Hive, Pig, and other big data frameworks on scalable clusters.
When to use: For processing large volumes of data using distributed computing frameworks.
Pros: Scalable, integrates with other AWS services, managed Hadoop ecosystem.
Cons: Higher cost than self-hosted solutions, complexity for simple use cases.
Cost: $0.10 - $0.25 per hour per core, plus storage and data transfer costs.
Container Services (ECS/EKS)
Origin: Amazon ECS launched in 2014, EKS in 2017 as part of AWS container services
What it is: Container orchestration services for deploying and managing containerized applications.
How it works: ECS manages container deployment and orchestration, EKS provides Kubernetes compatibility.
When to use: For running microservices or containerized applications at scale.
Pros: Fully managed, integrates with AWS services, easy scaling.
Cons: Vendor lock-in, additional costs for container management.
Cost: $0.05 - $0.15 per container instance, plus Kubernetes management fees.
Content Delivery (CloudFront)
Origin: Amazon CloudFront launched in 2008 as part of AWS CDN services
What it is: Global content delivery network for fast delivery of web and video content.
How it works: Distributes content from edge locations worldwide to reduce latency.
When to use: For delivering web content, video streaming, or any content that benefits from global distribution.
Pros: Low latency, global distribution, DDoS protection, easy integration.
Cons: Additional cost for content delivery, limited customization options.
Cost: $0.08 - $0.15 per GB of data transferred, $0.0025 per request.
Analytics (QuickSight)
Origin: Amazon QuickSight launched in 2016 as part of AWS Business Intelligence
What it is: Business intelligence service for creating visualizations and dashboards.
How it works: Provides interactive dashboards, automated insights, and data visualization tools.
When to use: For business users who want to analyze data and create visual reports.
Pros: Easy to use, integrates with various data sources, real-time analytics.
Cons: Limited advanced analytics, cost per user increases with more users.
Cost: $10 - $25 per user/month for Standard edition, $50+ per user/month for Enterprise.
Event Streaming (Kinesis)
Origin: Amazon Kinesis launched in 2014 as part of AWS real-time data processing
What it is: Service for real-time processing of streaming data.
How it works: Collects, processes, and analyzes real-time data streams from various sources.
When to use: For applications that need real-time data processing or analytics.
Pros: Fully managed, scalable, integrates with other AWS services.
Cons: Limited control over processing logic, cost can increase with high data volume.
Cost: $0.025 per GB of data ingested, $0.01 per stream hour for processing.
Networking (VPC)
Origin: Virtual Private Cloud (VPC) launched in 2008 as part of AWS networking
What it is: Isolated virtual network in the cloud for running AWS resources.
How it works: Users can define subnets, security groups, and route tables within their VPC.
When to use: For creating secure, isolated environments for applications and services.
Pros: Network isolation, security control, flexible configuration.
Cons: Requires more configuration than default networking, additional costs for VPC features.
Cost: $0.01 per VPC hour, $0.05 per subnet hour for network access.
Identity & Access Management (IAM)
Origin: AWS Identity and Access Management (IAM) launched in 2009 as core AWS service
What it is: Service for controlling access to AWS resources with fine-grained permissions.
How it works: Allows creation of users, groups, roles, and policies to manage access.
When to use: For securing AWS resources and managing user permissions across organizations.
Pros: Granular control, multi-factor authentication support, integration with other services.
Cons: Complex configuration for large organizations, ongoing maintenance required.
Cost: Free to use, no additional cost for IAM features.
Machine Learning (AI/ML)
Origin: AWS AI/ML services launched in 2015 as part of broader cloud AI strategy
What it is: Comprehensive suite of machine learning tools and services for developers.
How it works: Includes pre-trained models, automated ML, and custom model building capabilities.
When to use: For developers and data scientists who want to integrate AI capabilities into applications.
Pros: Easy integration, pre-built models, comprehensive documentation.
Cons: Limited customization, cost can increase with high usage.
Cost: Varies by service, from $0.01 - $5.00 per hour for training instances.
Disaster Recovery (S3 Glacier)
Origin: Amazon Glacier launched in 2012 as part of AWS long-term storage
What it is: Secure, durable, and cost-effective storage for backup and archiving.
How it works: Provides three retrieval options: Expedited, Standard, and Bulk for different recovery times.
When to use: For long-term backup, compliance archiving, or disaster recovery solutions.
Pros: Extremely low-cost storage, secure, durable for long-term retention.
Cons: Longer retrieval times, more complex to restore than standard storage.
Cost: $0.002 per GB/month for Glacier, $0.004 per GB/month for Glacier Deep Archive.
API Gateway
Origin: AWS API Gateway launched in 2014 as part of AWS API management
What it is: Fully managed service for creating, publishing, and managing APIs.
How it works: Provides endpoints for web services, handles authentication, rate limiting, and monitoring.
When to use: For creating RESTful APIs or WebSocket APIs for mobile, web, and IoT applications.
Pros: Fully managed, built-in security, integration with other AWS services.
Cons: Cost increases with high request volume, limited customization for complex routing.
Cost: $3.50 per million API calls, $0.0001 per GB of data transferred.
Auto Scaling
Origin: AWS Auto Scaling launched in 2009 as part of EC2 service features
What it is: Service that automatically adjusts compute capacity to maintain performance.
How it works: Monitors application metrics and scales EC2 instances up or down based on defined policies.
When to use: For applications with variable workloads that need automatic scaling.
Pros: Cost optimization, automatic response to load changes, reduces manual intervention.
Cons: Potential for over-scaling, configuration complexity, limited policy options.
Cost: Free to use, only charged for underlying EC2 instances and other services used.
Docker Container Services
Origin: Amazon ECS and EKS launched in 2014 and 2017 respectively as part of AWS container ecosystem
What it is: Managed container services that simplify running Docker applications.
How it works: Provides orchestration for containerized applications using Docker containers.
When to use: For deploying microservices or containerized applications that require orchestration.
Pros: No need to manage infrastructure, integrates with other AWS services, easy deployment.
Cons: Vendor lock-in, costs associated with container management.
Cost: $0.05 - $0.15 per container instance, plus Kubernetes management fees.
Web Application Firewall (WAF)
Origin: AWS WAF launched in 2015 as part of AWS security services
What it is: Security service that protects web applications from common web exploits.
How it works: Creates rules to block malicious traffic and protect against OWASP top 10 threats.
When to use: For protecting web applications from DDoS attacks, SQL injection, and XSS.
Pros: Easy to implement, protects against common threats, integrates with CloudFront.
Cons: May block legitimate traffic, requires ongoing rule maintenance.
Cost: $0.005 per rule per hour, $0.02 per GB of traffic processed.
EventBridge
Origin: Amazon EventBridge launched in 2019 as part of AWS event-driven architecture
What it is: Service for routing events between AWS services and applications.
How it works: Processes events from sources and routes them to target services based on rules.
When to use: For building event-driven architectures that respond to system changes or external events.
Pros: Fully managed, integrates with all AWS services, easy to configure.
Cons: Cost increases with high event volume, limited customization of event routing.
Cost: $0.001 per event, $0.00005 per rule per hour.
CodePipeline
Origin: AWS CodePipeline launched in 2015 as part of AWS DevOps services
What it is: Continuous delivery service for automating software release processes.
How it works: Automates the build, test, and deployment process with customizable pipelines.
When to use: For teams that want to automate their software release process and reduce manual steps.
Pros: Easy to set up, integrates with other AWS services, provides visibility into pipeline execution.
Cons: Complex configurations for advanced use cases, limited customization of steps.
Cost: $0.01 per pipeline hour, $0.005 per pipeline execution.
CloudWatch
Origin: AWS CloudWatch launched in 2009 as part of AWS monitoring services
What it is: Monitoring and observability service for AWS resources and applications.
How it works: Collects metrics, logs, and events to provide insights into application performance.
When to use: For monitoring application performance, detecting issues, and gaining operational insights.
Pros: Comprehensive monitoring, integrates with all AWS services, built-in dashboards.
Cons: Can become expensive with high volume of data, requires configuration for effective use.
Cost: $0.30 per GB of data stored, $0.001 per metric stored.
Route 53
Origin: Amazon Route 53 launched in 2004 as part of AWS DNS services
What it is: Highly available and scalable DNS web service for directing traffic to applications.
How it works: Maps domain names to IP addresses and provides routing policies for traffic distribution.
When to use: For managing DNS records, routing traffic to applications, and providing failover capabilities.
Pros: Highly reliable, global service, easy to configure, supports health checks.
Cons: Cost increases with high query volume, limited customization for complex routing.
Cost: $0.50 per million queries, $0.05 per hosted zone.
SNS (Simple Notification Service)
Origin: AWS SNS launched in 2009 as part of AWS messaging services
What it is: Messaging service that enables sending notifications to multiple endpoints.
How it works: Publishes messages to topics that subscribers can receive via email, SMS, or HTTP.
When to use: For sending real-time notifications or triggering workflows in response to events.
Pros: Simple to use, supports multiple endpoints, built-in integration with other services.
Cons: Not suitable for high-volume message delivery, limited message retention.
Cost: $0.50 per million messages, $0.00001 per message for delivery.
SQS (Simple Queue Service)
Origin: AWS SQS launched in 2009 as part of AWS messaging services
What it is: Message queuing service that decouples applications and processes.
How it works: Stores messages in queues and delivers them to consumers when ready.
When to use: For building scalable applications that need to process messages asynchronously.
Pros: Fully managed, supports both standard and FIFO queues, built-in integration.
Cons: Message processing delays, cost increases with high queue usage.
Cost: $0.0004 per 1,000 messages for standard queues, $0.0001 per 1,000 messages for FIFO.
Elastic Load Balancing
Origin: AWS ELB launched in 2009 as part of EC2 services for traffic distribution
What it is: Service that distributes incoming application traffic across multiple instances.
How it works: Automatically routes traffic to healthy instances based on load balancing algorithms.
When to use: For ensuring high availability and fault tolerance for applications.
Pros: Built-in health checks, automatic scaling, supports multiple load balancing types.
Cons: Additional cost for load balancing, configuration complexity for advanced use cases.
Cost: $0.02 per hour for each load balancer, $0.0001 per GB of data processed.
CloudFormation
Origin: AWS CloudFormation launched in 2010 as part of AWS infrastructure as code
What it is: Service that enables creating and managing AWS resources through templates.
How it works: Uses JSON or YAML templates to define and provision infrastructure automatically.
When to use: For replicating environments, managing infrastructure as code, and ensuring consistency.
Pros: Infrastructure as code, version control support, easy environment replication.
Cons: Learning curve for template syntax, limited debugging capabilities.
Cost: Free to use, no additional cost for template execution.
EFS (Elastic File System)
Origin: AWS EFS launched in 2012 as part of AWS storage services
What it is: Scalable file storage service for use with EC2 instances.
How it works: Provides shared file storage that can be mounted to multiple EC2 instances simultaneously.
When to use: For applications that need shared file storage across multiple instances or servers.
Pros: Scalable, fully managed, supports concurrent access from multiple instances.
Cons: Higher cost than EBS, latency compared to local storage.
Cost: $0.03 per GB-month for provisioned storage, $0.01 per GB-month for provisioned throughput.
CloudTrail
Origin: AWS CloudTrail launched in 2012 as part of AWS security and compliance services
What it is: Service that logs AWS API calls and events for security monitoring and compliance.
How it works: Records API calls made to AWS services and stores them in log files.
When to use: For security auditing, compliance monitoring, and troubleshooting.
Pros: Comprehensive logging, integrates with other AWS services, provides audit trails.
Cons: Storage costs increase with large volumes of logs, requires ongoing analysis.
Cost: $0.10 per 1,000 log file events, $0.02 per GB of logs stored.
KMS (Key Management Service)
Origin: AWS KMS launched in 2014 as part of AWS security services
What it is: Managed service for creating and controlling encryption keys.
How it works: Provides centralized key management and encryption for AWS services.
When to use: For protecting sensitive data at rest and ensuring compliance with encryption requirements.
Pros: Fully managed, integrates with other AWS services, supports key rotation.
Cons: Cost per key and usage, limited customization for key policies.
Cost: $0.03 per key per month, $0.005 per 1,000 key operations.
RDS (Relational Database Service)
Origin: AWS RDS launched in 2009 as part of AWS database services
What it is: Managed database service that supports multiple engines (MySQL, PostgreSQL, Oracle).
How it works: Provides automated backups, patching, and scaling with minimal administration.
When to use: For applications requiring relational database capabilities with managed infrastructure.
Pros: High availability, automated backups, easy scaling, integrated with other AWS services.
Cons: Limited customization, potential for vendor lock-in, higher cost than self-managed.
Cost: $0.12 - $1.50 per hour depending on instance type and database engine.
DynamoDB
Origin: AWS DynamoDB launched in 2012 as part of NoSQL database services
What it is: Fully managed NoSQL database service with single-digit millisecond latency.
How it works: Provides key-value and document storage with automatic scaling and indexing.
When to use: For applications requiring high-performance, low-latency database operations.
Pros: Fully managed, automatic scaling, low latency, built-in security features.
Cons: Limited query capabilities, cost increases with high throughput usage.
Cost: $0.25 per million read capacity units, $0.25 per million write capacity units.
