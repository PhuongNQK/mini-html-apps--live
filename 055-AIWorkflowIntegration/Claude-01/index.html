16 Building Blocks
The atomic components all approaches share and recombine. Mastering these primitives is more durable than mastering any single approach.
Context Management
⬜
Context Window
The working memory of an AI agent. Standard (~200k tokens) or extended (1M+). Determines how much the agent can "see" at once — the single biggest architectural lever.
All approaches
🔍
RAG / Vector Store
Retrieve relevant chunks from a large corpus into a smaller context. Enables "infinite" knowledge access without infinite context cost. Critical for large codebases.
Std context · Agentic · Hybrid
📋
Memory / Scratchpad
Structured state that persists across agent steps or sessions. Enables multi-pass work without re-reading source material. Ranges from key-value to graph memory.
Agentic · Std context · Hybrid
📁
Codebase Loader
Mechanism to load partial or full codebases into context — file selection heuristics, dependency graph traversal, chunking strategies, and relevance scoring.
Big context · Std context
Planning & Execution
🌳
Task Decomposer
Breaks high-level goals into executable subtasks with dependencies. The core planning primitive. Can be rule-based (fast, predictable) or AI-generated (flexible, expensive).
Agentic · Std context · Hybrid
🔀
PR / Diff Generator
Produces a concrete, reviewable change set against a target branch. The primary unit of delivery. Scope ranges from one file to hundreds — set intentionally, not by default.
All approaches
🔄
Self-Testing Loop
Agent runs tests, observes failures, and retries without human intervention. Dramatically improves output quality. The single highest-leverage mechanical improvement to any workflow.
Agentic · Big context · Std context
🪞
Reflection / Critique
A second AI pass that reviews the first output for errors, inconsistencies, or spec violations. Can be a different model, a different prompt framing, or a structured checklist.
Agentic · Spec-driven · Hybrid
Human–AI Interface
🛑
Human Checkpoint
Defined pause point where a human reviews, approves, or corrects before the agent continues. The primary risk control mechanism. Define checkpoint placement before designing the workflow.
All approaches (critical in high-risk)
📄
Formal Specification
OpenAPI, PRD, ADR, data contract, or schema that serves as ground truth. AI generates from this; humans write and maintain it. In regulated environments, the spec is also a compliance artifact.
Spec-driven · Hybrid
🧩
Skill / Tool Registry
Library of tested, versioned AI competencies. Agents select skills by task type. Grows as the team learns what works. The institutional memory of your AI practice.
Skill-driven · Agentic · Hybrid
📡
Feedback Signal
Structured input from humans or automated tests that shapes subsequent agent behavior. The compounding flywheel of any AI workflow. Without it, quality plateaus immediately.
All approaches
Infrastructure
🧭
Orchestrator
Routes tasks to the right agent, approach, or skill. Can be a human process, a rules engine, or an AI planner. The cognitive center of hybrid systems — its quality determines system quality.
Agentic · Hybrid
⏱
Async Runner
Long-running compute environment for autonomous agent work. Think CI/CD extended to hours or days. Requires checkpointing, observability, and graceful failure handling.
Big context · Std context · Agentic
📜
Audit / Trace Log
Every AI decision, tool call, and output captured in structured form for replay, debugging, and compliance. Non-negotiable in regulated environments. Design the log schema before the workflow.
All approaches (non-optional in banking)
📊
Eval Framework
Automated or human-scored suite that measures AI output quality over time. Without evals, you can't know if workflows are improving or degrading after model updates or requirement drift.

Section 04
Eight Principles
Durable rules that hold across all approaches, team sizes, and domains. These survive model changes, tooling shifts, and org reorgs.
01

Human in the Loop at Risk Boundaries

Every AI workflow has points where errors compound — before irreversible actions, before production deployment, before touching shared financial state. Mandate human checkpoints at these exact boundaries regardless of how autonomous the rest of the workflow is. The question isn't whether to checkpoint, but where.

Corollary: define your risk boundaries before designing the workflow, not after. In banking, the boundaries are: any write to account state, any compliance-affecting output, any change to a regulatory calculation.
02

Match Context Scope to Task Cohesion

Use the smallest context that preserves the coherence the task actually needs. A bug fix needs one module, not the full codebase. A cross-cutting refactor may need more. Over-loading context wastes compute and dilutes attention; under-loading breaks coherence and produces subtly wrong outputs.

Rule of thumb: if the AI can't see the interfaces it's implementing against, the context is too small. If it takes more than 5 minutes to construct the context, it's probably too large.
03

Specs Before Prompts

A well-written specification is the most powerful AI prompt you can write. Invest in formalizing requirements — OpenAPI, ADRs, data contracts — before optimizing prompts. Specs are durable and serve as eval criteria. Prompts are ephemeral and drift as models change.

In banking: specs double as compliance artifacts. Writing a good OpenAPI spec for a debt classification API produces both the AI's instructions and your audit evidence simultaneously.
04

Build Skills Before Agents

Agentic autonomy amplifies whatever competencies the agent has. If the underlying skills are unreliable, an autonomous agent will fail faster and more expensively than a manual process. Validate each skill in isolation before composing them into agent pipelines. A pipeline is only as reliable as its weakest skill.

Practical standard: run each skill with 20 representative test cases. If pass rate <85%, fix the skill before connecting it to other skills or agent loops.
05

Evals Are the Product

Without a way to measure output quality, you're guessing. Build eval suites before or alongside every AI workflow. Evals tell you when a workflow degrades after a model update, when it's safe to reduce human oversight, and which approach to choose for a given task type. The eval suite is your most valuable artifact.

Minimum viable eval: 10 golden examples with expected outputs + one automated scorer. Ship evals with every new workflow, not as an afterthought.
06

Log Everything, Replay Anything

Every AI action — inputs, tool calls, intermediate outputs, final output — should be captured in a structured trace. This enables debugging when autonomous runs go wrong, compliance audits when regulators ask, and root-cause analysis when outputs drift unexpectedly. Especially critical when agents run unsupervised for days.

In regulated systems: trace logs are non-optional. They are your audit trail. Design the log schema before the workflow schema — the log is primary, the workflow is secondary.
07

Start Narrow, Expand Deliberately

Don't design the full agentic pipeline on day one. Pick one high-value, lower-risk task, instrument it with evals and logs, learn from it for 4–6 weeks, then expand. The shape of your AI workflow should evolve with your empirical understanding of where AI excels and where it needs guardrails in your specific domain.

Good first targets: documentation generation, test suite writing, migration script generation, audit log summarization. High value, low blast radius if wrong.
08

Treat Approach Selection as Architecture

Choosing between spec-driven, agentic, or context-driven is an architectural decision — not a prompt engineering decision. It determines cost structure, risk profile, team workflow, and system boundaries. Make the choice deliberately and document the rationale. Revisit it annually as models and tooling evolve.

Anti-pattern: picking an approach because it's trendy or because another team uses it. The decision must follow from your specific task's coherence requirements and risk profile.
Section 05
Decision Framework
Answer five questions. The framework triangulates the best approach for your specific task and context.
The five questions below are ordered by impact — requirement clarity is the single biggest predictor of approach fit. Answer all five for the most precise recommendation. The framework handles mixed signals by reasoning across the full answer profile.
Question 01 of 05 — Most decisive
How well-defined are the requirements?
This is the strongest single predictor of which approach will succeed.
Formal spec exists (OpenAPI, PRD, data contract) Partially defined, will evolve Open-ended / exploratory
Question 02 of 05
How large is the codebase involved?
Determines whether a single context window can hold the relevant code.
Small (<50k tokens — fits comfortably) Medium (50k–500k — needs selective loading) Large (>500k — requires RAG or tight scope)
Question 03 of 05
How frequently do requirements change?
Determines the cost of re-running agents or regenerating from scratch.
Stable — months between changes Moderate — weekly changes expected Frequent — daily or continuous changes
Question 04 of 05
What is the risk profile of errors?
High-risk domains need more human oversight engineered into the workflow.
High — financial data, compliance, production Medium — internal tools, staging environments Low — docs, scripts, non-critical automation
Question 05 of 05
Does this task recur across projects?
Recurring tasks justify the upfront investment of building a reusable, tested skill.
Yes — similar tasks appear across projects or teams No — one-off or rarely recurring

Regulatory Change Implementation
Risk: Very High · Duration: Days · Compliance-critical
Step 01Human + AI Assist
Translate circular into delta spec
Human (AI-assisted) reads the SBV circular and converts the regulatory delta into a structured diff spec: which validation rules changed, which fields are new, which calculations are modified. The delta spec is the master input for all downstream steps.

Step 02Spec-Driven

AI reads delta spec against master system spec and outputs a precise impact map: which modules need changes, which APIs break, which tests must be updated. Human validates the impact map before any code generation begins.

Step 03Standard Context ×N
Parallel scoped agent runs per impacted module
One agent run per impacted module, each with isolated scoped context: module code + delta spec + existing tests. Runs execute in parallel. Each produces a focused PR. No cross-module contamination. Merge order is declared in the impact map.

Step 04Spec-Driven
Regression suite generation from delta spec
AI generates a full regression test suite from delta spec assertions. Every changed rule produces a corresponding test. Tests validate that all impacted modules correctly implement the new regulatory requirements. Becomes part of the permanent test suite.

Legal + compliance sign-off before merge
All PRs reviewed by compliance officer. Each change traced to its delta spec entry. Trace log provides SBV audit evidence. No merge proceeds without sign-off. Post-merge: auto-generate compliance change report for regulatory filing.
